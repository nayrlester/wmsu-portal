1. Universal access (Portal & Identity)

1.1 Recommended path (SSO)

  1. Start the stack: Base API (3500), Identity (3411), Portal (5173), and the app you need (see section 2).
  2. Open WMSU Unified Access Portal: http://127.0.0.1:5173
  3. Sign in with your University Identity email and password.
  4. Complete MFA if your account requires it.
  5. On the launcher, click the platform tile (USiS, UFMS, TORMS, etc.). SSO opens the app in a new tab with your session.
  6. Inside the app, menus depend on your Identity role, not only the platform tile (see section 1.3).

1.2 Direct URL (per app)

You may open each web client directly (e.g. http://127.0.0.1:5180/login). You still authenticate through Identity when dual-auth is enabled.

1.3 Two layers of access

LayerWho sets itWhat it controls
PlatformPortal Admin → user platformsLauncher tile + ability to SSO into that product (enrollment, finance, …)
RolePortal Admin → user rolesMenus and API permissions inside the product (student, registrar, cashier, …)
Example: student role + enrollment platform → USiS student portal only. identity_admin → broad USiS registrar/faculty menus when enrollment is assigned.

4. USiS (Enrollment) — by role

4.1 Student journey

  1. Portal → Enrollment (USiS) or 5180/login as student@identity.local.
  2. Dashboard /student
  3. Enrollment /student/enrollment — start/continue term.
  4. Academic advising /student/advising — after faculty endorses, pick one advised course if multiple are offered.
  5. Subject selection /student/subjects — irregular picks / alternates when allowed.
  6. Assessment forms /student/assessments — after registrar assesses.
  7. Payment status /student/payments — pay at UFMS cashier (production).
  8. Enrollment status /student/status — confirm registered.
  9. COR /student/cor · Schedule /student/schedule

4.2 Faculty / adviser journey

  1. Sign in with advising.write (demo: admin@identity.local).
  2. Academic advising /faculty/advising — start or open session.
  3. Session /faculty/advising/{sessionId}: check advisable courses, pick a section per subject, approve underload if needed, Endorse advising.
  4. Grade encoding /faculty/grades/encode after classes are registered.

4.3 Registrar journey

  1. Applicants /registrar/applicants — admit (creates student + optional login).
  2. Student records /registrar/students — Create login if Portal link missing.
  3. Academic structure /registrar/academic — sections, meetings, Scheduling desk (block encode, utilization, roster CSV).
  4. Registration approval /registrar/registration — Assess → Verify payment → Registrar approve → Register.
  5. Enrollments /registrar/enrollments · Reports /registrar/reports

5. UFMS (Finance)

  1. Portal → Finance or http://127.0.0.1:5182 with finance platform + role (cashier, finance staff, or admin@identity.local).
  2. Dashboard — budget and collections overview.
  3. Tuition & payment plans — configure plans (admin).
  4. Cashier / POS — record payment against USiS assessment number.
  5. Return to USiS /registrar/registration → Verify payment.

Local dev: optional USIS_DEV_PAYMENT_BYPASS=true in base-api .env (restart API) — not for production.

6. TORMS (Records)

  1. Portal → Records or http://127.0.0.1:5181 with records platform.
  2. Staff: transcript requests, certifications, document verification workflows per your role pack.
  3. Students: self-service only if role includes student records permissions (usually staff-facing).

7. ULMIS (Library)

  1. Staff: Portal → Library → http://127.0.0.1:5183 (library platform).
  2. Cataloging, circulation, acquisitions, member services — menus by library role pack.
  3. Public OPAC: http://127.0.0.1:5186 (no staff login).
  4. Kiosk: http://127.0.0.1:5187 for self-check / quick patron tasks.

8. UIMS (Inventory)

  1. Portal → Inventory or http://127.0.0.1:5184 (inventory platform).
  2. Items & catalog → stock & warehouses → assets → requisitions / counts — Supply Office workflows.

9. DocsTrack (Documents)

  1. Portal → Documents or http://127.0.0.1:5185.
  2. Create/track documents, routing, approvals, public track link, records lifecycle per role.

10. Portal Admin & MDM

  1. Portal Admin (Identity console from launcher or Identity app): users, roles, platforms, MFA.
  2. MDM Admin http://127.0.0.1:5174 — master data / platform ops (separate from day-to-day USiS work).
