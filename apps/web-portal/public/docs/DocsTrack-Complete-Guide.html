Chapter 1 — Introduction

Purpose of the System

DocsTrack is a multi-tenant document tracking and workflow automation platform. Organizations use it to:

  • Register official documents with unique tracking numbers (DTS-2026-0000042)
  • Route records through multi-step approval workflows (sequential, parallel, conditional, SLA)
  • Operate a records desk: requests/release, digitization/OCR QA, receiving, archives & disposal
  • Maintain a complete audit trail of who acted and when
  • Share public status with external parties (optional)
  • Search across documents, files, OCR text, users, and workflows

Key Benefits

Benefit Business value
Traceability Every action logged; supports compliance reviews
Standardized routing Approvers receive work in a single queue
Version control File and content revisions tracked as v0.1, v1, v1.1…
Draft privacy Drafts visible only to the creator until submitted
Public tracking Citizens/vendors check status without login
AI Help Desk Natural-language assistance inside the application

Chapter 6 — Records Management

DocsTrack includes university / LGU-style records desk modules under the Documents sidebar group. These close the UDMS request–release, digitization, receiving, and archival loops.

6.1 Record Requests & Release Desk

Routes: /app/records/requests, /app/records/requests/new, /app/records/requests/:id
Permissions: records.request.create (request), records.release.manage (desk actions)

Purpose: Staff request access to registered records (view, download, or physical checkout). Release officers approve/deny, check out, and return items with an append-only release log.

Business scenario: A researcher requests physical checkout of a personnel folder. The records officer approves, logs checkout, then marks return when the folder is back.

Steps — create a request:

  1. Open Record Requests → New request.
  2. Enter Purpose (required).
  3. Choose Access mode: View only / Download / Physical checkout.
  4. Optionally set needed-by and due dates.
  5. Select one or more documents from the list.
  6. Select Submit request.

Desk actions (release officers): Approve, Deny, Release (checkout), Return, Cancel — available on the request detail page when status allows.

Expected result: Request number assigned (e.g., RR-2026-0000001). Notifications fire on submit / approve / deny / release / return.

6.2 Digitization & OCR QA

Route: /app/records/digitization
Permission: records.digitization.manage

Purpose: Batch paper scan intake with OCR confidence, indexing checklist, and physical box/folder linkage.

Steps:

  1. Open Digitization → New batch → enter title/notes → Create batch.
  2. On the batch board, Add scan item (label, optional linked document, box/folder IDs).
  3. For each queued item, capture or upload JPEG/PNG pages or a PDF (camera capture supported on mobile).
  4. The system builds a PDF, checks duplicate content hash, runs OCR / AI, and shows OCR confidence.
  5. Complete the indexing checklist, confirm box ID, then Pass QA & link (or Fail QA).
  6. When all items are done, Complete batch.

QA rule: Passing QA requires checklist completion, a physical box ID, and adequate OCR confidence (low-confidence scans should be re-scanned or failed).

6.3 Receiving Desk

Route: /app/records/receiving
Permission: records.receiving.manage

Purpose: Log inbound channels (walk-in, email, courier, portal, internal) with a daily receiving log and printable acknowledgment.

Steps:

  1. Open Receiving Desk.
  2. Filter by Date for the daily log.
  3. Select Log receipt — title, channel, sender, optional box/folder, description.
  4. Select Save receipt.
  5. On the detail page, Register to link or create a document, and print/view the acknowledgment.

Expected result: Receipt number (e.g., RCP-2026-0000001) and optional linked tracking number after registration.

6.4 Archives, Disposal & Legal Hold

Route: /app/records/archives
Permission: records.archives.manage

Purpose: Archival transfer packages, disposal requests with certificate numbers, and legal hold controls.

Archival transfers

  1. Open Archives → Transfers tab.
  2. Enter a transfer title and select documents.
  3. Create transfer → Approve → Complete & archive (moves lifecycle to archived).

Disposal requests

  1. Open Disposals tab.
  2. Enter title, justification, and select documents (legal hold blocks disposal).
  3. Create disposal request → Approve → Execute disposal.
  4. Note the generated certificate number for audit evidence.

Legal hold

On Document detail, records officers can Set hold / Release with a reason. Held documents cannot be disposed.

6.5 Retention schedules

Settings → Retention (permission records.retention.manage) configures NAP-aligned retention schedules used when creating documents and computing retention due dates. Inventory and due-for-archive views are available to reporting roles via the records inventory API / Reports operations pack.

Chapter 8 — Workflow Process

Submission

  1. Creator completes draft (files and/or written content).
  2. Select Submit for processing on the draft version card.
  3. Status changes to Pending Approval; workflow instance starts.
  4. Draft becomes visible to involved users (approvers, assignees).

Multi-step designer (administrators)

Route: /app/workflows · Permission: workflows.manage

Administrators create draft workflows with one or more steps:

Step type Behavior
Sequential One assignee role at a time
Parallel Sibling steps in a parallel group must complete
Conditional Advances when document priority matches the configured rule
SLA hours Per-step due window; breaches surface in operations reports

Publish the draft before documents can use it. Link workflows to document types under Settings → Document setup.

Review & Approval

[Image: assets/screenshots/30-approvals-queue.png]

  1. Open Approvals or dashboard widget.
  2. Select a pending document.
  3. Review files, timeline, activity, and OCR metadata if present.
  4. Choose Approve, Return, or Reject (reject requires comments).

Chapter 15 — Best Practices

Naming Standards

  • Titles: {Subject} — {Reference} (e.g., Office Supplies PR — Q2 2026)
  • Avoid generic titles like "Test" in production

Approval Workflows

  • Configure default workflow before go-live
  • Prefer multi-step published workflows with SLA hours for critical document types
  • Assign approver role to users who action steps
  • Use Return for fixable issues; Reject for terminal declines

Document & records management

  • Submit only when attachments are final
  • Use version notes when replacing files
  • Prefer revising same tracking number after external circulation
  • Run digitization batches daily; clear QA board before completing
  • Apply legal hold before litigation or audit freezes; never dispose held records
  • Export the ops CSV monthly for SLA / OCR / scan evidence packs

Search Optimization

  • Include tracking numbers in email subject lines
  • Correct OCR metadata when extraction is wrong so search stays accurate
  • Wait 1–2 minutes after upload for search index refresh

Security Practices

  • Do not share login credentials
  • Use Private visibility unless public tracking is required
  • Use Confidential / Restricted classifications for sensitive records
  • Review Team and Roles pages quarterly for inactive accounts and excess permissions

Documents in Draft status are visible only to their creator. Other users—including administrators—cannot see draft records in list views or search results. Once submitted, the document becomes visible to users with appropriate permissions and workflow assignees.

Create a workflow

  1. Navigate to Workflows (/app/workflows).
  2. Select Create workflow — enter name and description.
  3. Build the graph in the workflow builder:
    • Start and End nodes (required)
    • Sequential steps — one approver at a time
    • Parallel steps — multiple branches at the same stage
    • Conditional steps — branch on document metadata
  4. Configure each step:
    • Assignee — specific user, role (e.g., Approver), or department head
    • Target document status — optional status transition (e.g., pending_review)
    • SLA hours — optional deadline for breach detection
  5. Publish when ready. Only published workflows execute on submission.

In the current web builder, steps are authored as a multi-step list (sequential / parallel / conditional + SLA hours). Parallel steps share a parallel group; conditional steps can gate on document priority.

Modify a published workflow

Edit draft workflows freely. For published workflows, duplicate or create a new version before major structural changes. In-flight documents retain their started workflow instance; changes apply to new submissions only.

Getting Started

What is DocsTrack?

DocsTrack is a multi-tenant document tracking and workflow platform. Organizations create official records with unique tracking numbers, route them through approval chains, attach files, and maintain a complete audit trail. Authenticated users work inside /app; external parties can check status on public documents without logging in.

[Image: assets/screenshots/01-landing-page.png]

Who should I contact for an account?

Contact your organization's DocsTrack tenant administrator (typically IT or a departmental lead). Tenant Owners and Admins manage invitations and roles on the Team page. Platform-wide issues are handled by a Super Administrator.

Which browsers are supported?

Current versions of Chrome, Edge, Firefox, and Safari. JavaScript must be enabled. DocsTrack is a responsive web application and works on tablets and phones, though complex workflow configuration is best on desktop.

How do I sign in?

Open your organization's DocsTrack URL and use the sign-in page with your work email and password. OAuth sign-in (Google or Microsoft) is available when configured by your deployment.

Until the UI is released, contact your tenant administrator to initiate a reset or receive a reset link by email if your deployment has outbound mail configured.

What happens after five failed login attempts?

Accounts are rate-limited for approximately 15 minutes after repeated failed attempts. Wait before retrying, or ask an administrator to verify your account is active.

Can external vendors or citizens log in?

Only users who have been invited receive accounts. External status checking for public documents uses the public tracking page at /track/{trackingNumber} — no login required.

How do I register a new organization?

New tenants can register through the public registration flow if enabled by your deployment.

On the document detail page, in list views, in notifications, and in approval queue cards. Copy it directly rather than retyping.

Documents and Drafts

How do I create a document?

Open Documents → Create, enter title and metadata, attach files or use the editor, then save as draft or submit for approval.

[Image: assets/screenshots/12-create-document.png]

Who can see my draft?

Draft documents and draft versions are visible only to the creator until the document is submitted. Other users — including administrators — cannot view draft records or draft file versions in lists, search, or detail views. This applies across the API, search index, and UI.

After submission, the document follows normal visibility and permission rules.

What is the difference between Draft and Pending Approval?

Status Editable by creator? In approver queue? Visible to others?
Draft Yes No Creator only
Pending Approval No Yes Users with documents.view
Returned Yes (files/metadata) No Users with documents.view
Approved / Rejected No No Users with documents.view

Why can't I delete a submitted document?

Delete is restricted to draft status and requires documents.delete. Submitted records must follow return, reject, or archival procedures to maintain audit integrity.

Can I edit a document after submitting?

Not while Pending Approval. If an approver returns the document, you can edit files and metadata again.

What file types can I upload?

Supported types:

Category Extensions
PDF .pdf
Microsoft Office .doc, .docx, .xls, .xlsx, .pptx
Images .png, .jpg, .jpeg
Text .txt, .csv

Is there a file size limit?

The default maximum is 25 MB per file. Plan limits and server configuration may impose additional quotas. Contact your administrator if large uploads fail consistently.

Can I attach multiple files?

Yes — during creation and while the document is in Draft or Returned status.

What are document types?

Administrator-defined categories (e.g., Contract, Purchase Request, Memo) that can trigger default workflows and metadata schemas.

What priorities are available?

Typically Low, Medium, High, and Urgent. Use Urgent sparingly so approvers can prioritize effectively.

Where is the documents list?

Approvals and Workflows

What is the Approvals queue?

Approvers see documents assigned to them on the Approvals page. Items appear when a document is Pending Approval and the user is the active step assignee.

[Image: assets/screenshots/30-approvals-queue.png]

What is the difference between Return and Reject?

  • Return — sends the document back to the originator for corrections; status becomes Returned; workflow instance is cancelled but the same tracking number can continue after resubmission.
  • Reject — denies the request; a comment is required; typically a terminal outcome.

Why don't I see Approve / Return / Reject buttons?

Common reasons:

  1. You lack documents.approve permission.
  2. You are not the active step assignee on the workflow.
  3. Document status is not Pending Approval (still draft, already approved, etc.).
  4. The workflow was not published before submission.

What happens on final approval?

Status becomes Approved, the workflow instance completes, and notifications are sent to relevant parties.

How do workflows get assigned?

Workflows route by step configuration — typically by role (e.g., Approver role) or department head. Document type or tenant default workflow determines which definition applies.

[Image: assets/screenshots/16-workflows-list.png]

Must I publish a workflow before it runs?

Yes. Unpublished workflow definitions do not start instances. Administrators publish from the workflow builder after configuration.

What is a parallel approval step?

Multiple assignees must all complete their action before the workflow advances to the next step.

Records desk (requests, digitization, receiving, archives)

How do I request access to a registered record?

Open Record Requests → New request, state your purpose, choose access mode (view / download / physical checkout), select documents, and submit. Release officers approve and check items out from the request detail page.

What is Digitization used for?

Digitization batches paper scans: upload or camera-capture pages, auto-build PDF, run OCR with confidence scoring, complete the indexing checklist, then link to a document with physical box/folder IDs.

What is the Receiving Desk?

The Receiving Desk logs inbound channels (walk-in, email, courier, portal, internal), produces a daily log, and can register a receipt into a tracked document with a printable acknowledgment.

How do archival transfer and disposal work?

Under Archives, create a transfer package (approve → complete archives the documents) or a disposal request (approve → execute). Disposal is blocked if any selected document is under legal hold. Execution issues a certificate number for audit evidence.

Why don't I see Digitization / Receiving / Archives in the sidebar?

Those items are permission-gated (records.digitization.manage, records.receiving.manage, records.archives.manage). Ask your administrator to assign the permission or run the records permissions seeder after an upgrade.

Part 11 — Best Practices

DocsTrack Best Practices and Common Mistakes

Operational guidance from implementation projects. Use alongside role-specific manuals.

Part 1: Best Practices

Document Naming

Use searchable, specific titles.

Poor: Contract
Good: Acme Corp — Master Service Agreement — 2026-2028

Include party names, document class, and period or reference code. Approvers scanning queues decide in seconds—titles are your headline.

Include internal reference codes when your ERP or finance system uses them (PO-8842 — Server Refresh).

Avoid special characters that break email subject lines or exports.

Department Routing

Set department at creation before submit. Meridian Corp routes Finance documents differently from HR—wrong department sends requests to the wrong queue.

Align departments with org chart during admin setup. Rename inactive departments rather than deleting when history exists.

Document department head assignments in implementation runbook even when UI assignment is pending—workflow steps depend on it.

Train staff on department picker during onboarding—most mis-routes are user selection errors, not engine failures.

Approval Management

Process queues daily. SLA breaches often start as one skipped afternoon.

Return with specifics. Reference section numbers, template versions, and required attachments—not "please fix."

Reject only when necessary. Return preserves relationship and tracking number for fixable issues.

Check Timeline on multi-step documents before assuming your approval is final.

Use priority honestly. Inflated Urgent flags train approvers to ignore priority.

File Upload Standards

One authoritative PDF for signed contracts when possible.

Filename before upload: Vendor-DocType-Date.pdf indexes better than scan003.pdf.

Avoid password-protected files unless approvers have passwords documented.

Redact personal data not needed for approval decision.

Verify upload on document detail before Submit—empty submissions waste cycle time.

Supported types: PDF, Word, Excel, PowerPoint, images, TXT, CSV.

Audit Compliance

Never delete submitted records to "clean up"—archive per policy.

Use DocsTrack actions instead of off-system email approvals when audit trail required.

Export activity for investigations from document Activity tab.

Review audit access quarterly—Viewer role should not hold audit permission unless justified.

AI Assistant confirmations are logged—treat Confirm on approve/reject as formal action.

Workflow Efficiency

Publish workflows before go-live. Draft workflows do not execute.

Match document types to workflows—avoid one generic flow for vastly different processes.

Set SLA hours realistically from historical approval times, not aspirational targets.

Limit parallel branches to necessary separation-of-duties cases—complexity slows troubleshooting.

Test end-to-end after every workflow change with a non-production document.

Review overdue metrics weekly on Reports dashboard.

Mistake 1: Submitting Before Upload Completes

Why: User clicked Submit while files still uploading or selected wrong tab (Editor with no content).

What happened: Vendor shared tracking link; internal negotiation comments exposed on public timeline (sanitized but status visible).

Mistake 3: Reject Instead of Return

What happened: Procurement rejected for missing signature; vendor relationship strained; new tracking number required for resubmission.
Why: Approver treated fixable gap as denial.
Avoid: Return with attachment checklist unless policy violation.

Mistake 4: Duplicate Documents for Same Transaction

What happened: Two tracking numbers for one PO; finance paid twice pending investigation.
Why: Staff did not search before create.
Avoid: Ctrl+K search by vendor and PO number first.

Mistake 5: Ignoring Return Remarks

What happened: Second submission returned for same missing clause.
Why: Originator edited description but not PDF.
Avoid: Read return comment aloud in team huddle; check off each item.

What happened: Staff told vendor approved; CFO step still pending.

Mistake 7: Wrong Role Assignment

Why: Never taught Ctrl+K tracking number lookup.

Part 12 — Creating a Document

Purpose

Creating a document registers a new record in DocsTrack when you need formal approval, a permanent audit trail, or an official tracking number. Use this workflow for contracts, memos, purchase requests, and any item that must move through your organization's approval chain.

DocsTrack replaces informal email threads with a single source of truth: one tracking number, versioned content, and a visible routing history.

When to use this

Create a document when:

  • A file or written request requires manager or multi-step approval
  • Department policy mandates a tracking number before processing
  • You need attachments and version history in one place

Do not create duplicate records for the same transaction. Search by tracking number or title first.

Before you start

  • Confirm Create Document appears in your sidebar (/app/documents/create). This requires the Create Documents permission.
