1. Overview

Identity Service is the central login hub and RS256 SSO issuer for:

Platform Codes
ULMIS (Library) library, library_opac, library_kiosk
HRIS Payroll hris
DocsTrack (CDTS) docstrack
Surface Prefix Auth
Service root / JWKS /, /.well-known/jwks.json Public
Docs /api/v1/docs* Public
Authentication /api/v1/auth/* Public login/refresh; Bearer for me/logout
Enrollment provision /api/v1/integrations/enrollment/* X-Service-Api-Key
Admin console API /api/v1/admin/* Bearer JWT + Identity Admin

Approximate route count: 18 HTTP registrations (including docs + health).

Clients (local):

App Port
Identity portal (apps/web) 3400
Identity API (apps/api) 3401

Content type for JSON bodies: application/json.

2. Authentication & Tokens

2.1 Token types

Token Use
Access token (JWT, RS256) Authorization: Bearer <accessToken>
Refresh token POST /api/v1/auth/refresh

Successful login returns a structure similar to:

{
  "data": {
    "accessToken": "…",
    "refreshToken": "…",
    "expiresIn": 900,
    "tokenType": "Bearer"
  }
}

Exact nesting follows OpenAPI / runtime responses.

2.2 Auth endpoints

Method Path Purpose
POST /api/v1/auth/login Email/password login
POST /api/v1/auth/refresh Rotate access token
POST /api/v1/auth/logout Invalidate session
GET /api/v1/auth/me Current user, roles, platforms

2.3 Demo credentials (dev)

Seeded when DEMO_SEED_PASSWORD is set in the API environment (never commit production passwords):

Email Role Platforms
admin@identity.local Identity Admin All + admin
student@identity.local Student Library, OPAC, Kiosk only
employee@identity.local Employee Library, HRIS, DocsTrack
nodocs@identity.local Employee Library, HRIS (no DocsTrack)

Password is whatever you set in DEMO_SEED_PASSWORD. Do not reuse production passwords here.

3. SSO & JWKS

Platforms verify Identity access tokens using JWKS:

GET /.well-known/jwks.json

Typical JWT claims include:

Claim Meaning
iss JWT_ISSUER
aud JWT_AUDIENCE
sub Identity user id
roles Role codes
apps Granted platform codes / deep-link context

Dual-mode SSO on platforms (AUTH_MODE=dual):

  1. User signs in on Identity portal
  2. Launcher opens {platform}/sso/callback#access_token=…&refresh_token=…
  3. Platform validates JWT via JWKS and links/provisions local user

Leave platform AUTH_MODE=local until Identity is ready.

6. Platform Grants

Students are Library-only. Identity clamps student platform codes to:

  • library
  • library_opac
  • library_kiosk

Students never receive hris or docstrack — enforced on enrollment provision, admin edits, launcher, and JWT apps claims.

8. Enrollment Integration

See also enrollment-integration.md.

All enrollment routes require:

X-Service-Api-Key: <ENROLLMENT_SERVICE_API_KEY>

Upsert one student

POST /api/v1/integrations/enrollment/students

{
  "externalId": "ENR-2026-00421",
  "email": "juan.dela.cruz@student.university.edu",
  "fullName": "Juan Dela Cruz",
  "studentNumber": "2026-00421",
  "status": "active"
}

Omitting password generates a one-time temporaryPassword on create (returned once).

Batch upsert

POST /api/v1/integrations/enrollment/students/batch with { "students": [ … ] } (max 500). Partial failures appear in data.errors.

Deactivate

POST /api/v1/integrations/enrollment/students/{externalId}/deactivate sets status=disabled.

9. Admin Surface

Admin routes require a valid Bearer access token for a user with Identity Admin privileges (middleware.auth + middleware.admin).

Create user body (illustrative):

{
  "email": "new.staff@university.edu",
  "fullName": "New Staff",
  "password": "<strong-password>",
  "roleCodes": ["employee"],
  "platformCodes": ["library", "hris", "docstrack"]
}

Student role codes force Library-only platforms even if HRIS/DocsTrack codes are sent.

10. Common Workflows

10.1 Portal login → launch platform

  1. POST /api/v1/auth/login
  2. GET /api/v1/auth/me (roles + platforms)
  3. Portal launcher redirects to platform SSO callback with tokens
  4. Platform validates JWT via JWKS

10.2 Enrollment → Library SSO

  1. Enrollment system upserts student via service key
  2. Student logs in on Identity (Library-only grants)
  3. ULMIS with AUTH_MODE=dual provisions/links member on first SSO
