Chapter 1 — Introduction

Purpose of the System

UIMS is a university-focused inventory and property accountability platform for Philippine government institutions. It is a standalone sibling of Identity Service, HRIS Payroll, ULMIS (Library), and UDMS — not embedded in HRIS, though it shares the same PostgreSQL database under an isolated uims schema.

Institutions use UIMS to:

  • Maintain a master catalog of consumables, supplies, and semi-expendable items with categories, barcodes, and CSV import
  • Operate warehouses and bins with real-time stock balances and an immutable movement ledger
  • Run stock movements: beginning balance, receive, issue, transfer, adjust, return, disposal, reserve, and release
  • Manage suppliers and office requisitions (draft → submit → approve/reject → fulfill)
  • Register and track Property, Plant & Equipment (PPE) assets with assignment, maintenance, retirement, and QR labels
  • Produce Commission on Audit (COA) forms: ICS, PAR, RPCPPE, IIRUP, and WMR
  • Conduct physical counts with a mobile Field PWA for barcode scanning
  • Calculate Government Accounting Manual (GAM) straight-line depreciation on PPE
  • Export mandated reports (CSV and print/PDF) and review audit logs for compliance

Key Benefits

Benefit Business value
COA-aligned workflows ICS, PAR, RPCPPE, IIRUP, WMR with approval audit trail
Dual auth Local JWT plus Enterprise Identity SSO (AUTH_MODE=dual)

Idempotent stock writes Idempotency-Key header prevents duplicate postings on retry

Chapter 2 — Accessing the System

Local URLs (development)

Surface URL
Staff web http://localhost:5200
API http://127.0.0.1:3334
Swagger / OpenAPI http://127.0.0.1:3334/api/v1/docs
SSO callback (Identity launch) http://localhost:5200/sso/callback
Identity Service (reference) http://127.0.0.1:3401

Local login

  1. Open the staff web URL (http://localhost:5200).
  2. Enter your email and password.
  3. After successful authentication, you are redirected to the Dashboard.

Seeded administrator (non-production only):

Field Value
Email admin@uims.local
Password password123
Role Administrator (all permissions)

Change this password before any production or shared-environment use.

Enterprise SSO (Identity launch)

When AUTH_MODE is dual or platform:

  1. Sign in to the University Platform Access portal (Identity Service).
  2. Launch the UIMS application (platform code: uims).
  3. Identity redirects to /sso/callback with tokens in the URL hash (#access_token=…&refresh_token=…).
  4. UIMS validates the platform JWT via JWKS, links or provisions the local user, and redirects to /dashboard.

If SSO fails and AUTH_MODE=dual, use local login as a fallback. In platform mode, Identity is required.

Session tips

  • If API calls fail with 401 Unauthorized, sign out and sign in again — the access token may have expired. Use refresh or re-login.
  • Confirm the API is running on port 3334 and that VITE_API_URL includes /api/v1.
  • Never share SERVICE_API_KEY or paste it into browser clients — it is for server-to-server (HRIS) calls only.
  • On shared tablets used for Field Mode, sign out at the end of each shift.

Chapter 6 — Items & Categories

Master catalog

Items represent consumables, supplies, semi-expendables, and catalogued stock SKUs. Each item typically includes:

  • SKU (unique stock-keeping unit code)
  • Name and optional description
  • Unit of measure (UOM)
  • Barcode for scanning
  • Category assignment
  • Brand, model, manufacturer
  • Fund source (for government accounting)
  • Minimum stock, reorder point, safety stock thresholds
  • Expiry tracking flag where applicable

Default valuation method for new items: weighted average.

Categories

Organize items into categories for reporting and browsing. Create categories before bulk item loads when possible.

Create an item (UI)

  1. Open Inventory → Items.
  2. Click Add Item (or equivalent).
  3. Fill required fields: SKU, name, UOM.
  4. Set reorder thresholds if you want low-stock dashboard alerts.
  5. Save.

CSV import

Items → Import CSV uploads a spreadsheet to POST /api/v1/items/import.

Constraint Value
Max rows per upload 2,000
Required columns sku, name
Permission items.write

Sample header row:

sku,name,uom,barcode,fundSource,brand,model,manufacturer,minStock,reorderPoint,description

Supported columns (case-flexible): sku, name, uom/unit, barcode, fundSource, brand, model, manufacturer, description, minStock, reorderPoint/reorderLevel, safetyStock.

Behavior:

  • Existing SKU → update in place
  • New SKU → create
  • Response includes { created, updated, errors[] } — review errors before assuming full success

Run imports first in a staging environment when loading large catalogs.

Permissions

Action Permission
View items and categories items.read
Create, edit, import, delete items.write

Chapter 8 — Stock Movements

Stock is the operational heart of UIMS. Every quantity change posts a transaction to the ledger and updates balances (on-hand, reserved, available) per item/warehouse/bin.

Movement types

Type Direction Typical use
beginning Inbound Opening balance at go-live or new warehouse
receive Inbound Goods receipt from supplier or donation
issue Outbound Issue to office, project, or requisition fulfillment
transfer Out + In Move stock between warehouses/bins
adjust +/- Cycle-count variance, correction
return Inbound Return unused stock to warehouse
disposal Outbound Write-off, expiry destruction, waste
reserve Hold Reserve quantity against an approved requisition
release Release hold Cancel or reduce a reservation

Web UI (Stock page)

The Movements tab exposes these forms:

UI label API type
Receipt (IN) receive
Issue (OUT) issue
Adjustment adjust
Return return
Disposal disposal
Reserve reserve
Release release

API-only in current web build: beginning (opening balance) and transfer. Use Swagger or an integration client until UI forms are added.

Balances and ledger

View Route / tab Purpose
Balances Stock → Balances On-hand, reserved, available per item/warehouse/bin
Transactions Stock → Movements history Chronological movement list
Item ledger Stock → Ledger (by item) Full audit trail for one SKU

Always verify balances after posting — especially after bulk receive or physical count reconciliation.

Idempotency-Key (integrations)

All stock write POST endpoints accept an optional HTTP header:

Idempotency-Key: <unique-client-generated-uuid>
Aspect Detail
Purpose Prevent duplicate postings when a client retries after timeout
TTL 24 hours (in-memory per API process; use Redis in multi-replica production)
Scope Stock writes only (beginning, receive, issue, transfer, adjust, return, disposal, reserve, release)
Behavior Same key + same org + same endpoint → returns cached response

The standard web UI does not send this header. Integrators and custom scripts should generate a fresh UUID per logical operation.

Linked workflows

  • Requisition fulfill auto-posts issue movements for approved line quantities.
  • Physical count reconcile auto-posts adjust movements for variances.

Permissions

Action Permission
View balances, ledger, transactions stock.read
Post movements stock.write

Create a requisition

  1. Inventory → Requisitions → New.
  2. Select requesting office and add line items (item, requested quantity).
  3. Save as draft.
  4. Submit when ready for approval.

Approve or reject

Approvers (typically Supply Officer) review submitted requisitions, set approved quantities per line, and approve or reject with reason.

Fulfill

On an approved requisition:

  1. Select the issuing warehouse.
  2. Enter issue quantities (≤ approved qty).
  3. Fulfill — system posts stock issue movements and sets fulfilledAt.

Chapter 12 — Physical Count & Field PWA

Physical count sessions

Physical inventory verifies system quantities against what is on the shelf or in the field.

Count types

Type Scope
stock Consumable / warehouse stock (default)
property PPE assets for RPCPPE support

Session statuses

stateDiagram-v2
  [*] --> open
  open --> counting: Start scanning
  counting --> reconciling: Reconcile
  reconciling --> reconciled: Variances posted
  reconciled --> closed: Close session
  closed --> [*]
Status Meaning
open Session created; accepts scan lines
counting Active field scanning in progress
reconciling Variance adjustments being posted
reconciled Adjustments complete

Session number format: PC-{YYYYMM}-{SEQ}

Desktop workflow

  1. Inventory → Physical Count → New — select warehouse, count type, and scope.
  2. Copy the Count ID (UUID) for Field Mode.
  3. After field scanning completes, open the session → Reconcile (posts stock adjust for variances).
  4. Close the session when variances are reviewed.

Only open sessions accept new scan lines.

UIMS Field PWA

Field Mode (/field) is a installable progressive web app for tablets and phones.

Install

  1. Open http://localhost:5200/field on the device browser.
  2. Use Add to Home Screen (manifest name: UIMS Field).
  3. Confirm API connectivity via /health on campus Wi‑Fi before large count events.

Field features

Feature Detail
Count ID Links scans to a physical count session
Camera barcode scan QR, Code128, EAN, UPC via BarcodeDetector
Manual entry Barcode + quantity when camera unavailable
Geolocation GPS coordinates recorded per scan line
Photo evidence Optional attachment (large photos may queue locally)
Offline queue Scans stored in localStorage when offline
Sync Posts queued lines to POST /counts/:id/scan

Deep link: /field?countId={uuid} pre-fills the Count ID.

Field workflow checklist

  1. Create count on desktop → copy Count ID.
  2. Open Field Mode on tablet → enter or deep-link Count ID.
  3. Scan items/assets; queue builds if offline.
  4. Sync when back online.
  5. Return to desktop → Reconcile → Close.

Chapter 13 — GAM Depreciation

UIMS implements Government Accounting Manual (GAM)–style straight-line depreciation on PPE.

Depreciation profile

Before running depreciation, create a profile per asset:

Field Description
Asset ID UUID of the PPE record
Method straight_line (only method currently)
Useful life Months
Residual rate Percentage of acquisition cost
Acquisition cost Capitalized amount
In-service date Depreciation start anchor

Property → Depreciation → Profiles → Add Profile

Run depreciation

  1. Open Run Depreciation.
  2. Select period year and month.
  3. Optionally limit to a single asset (blank = all active profiles).
  4. Execute — creates asset_depreciation_entries and property ledger credits.

Runs are idempotent per asset/period — duplicate runs for the same month are skipped.

When book value reaches residual value, the profile is deactivated.

Views

Tab Content
Profile Per-asset depreciation setup
Lapsing Schedule Future period charges
Property Ledger Posted depreciation entries

Review entries before exporting to finance.

Chapter 18 — FAQ (Staff)

Q: Is UIMS part of HRIS?
A: No. UIMS is a standalone sibling system. It shares the Postgres host with HRIS but uses an isolated uims schema.

Q: What is the default admin login?
A: Non-production only: admin@uims.local / password123. Change immediately in production.

Q: Can I use SSO and local login together?
A: Yes, when AUTH_MODE=dual. Use Identity launch for SSO; local form remains as fallback.

Q: Where are beginning balance and transfer movements?
A: Supported by API; web forms may be added later. Use Swagger at /api/v1/docs if needed.

Q: Why is Stock Value zero on the dashboard?
A: The summary KPI is not yet computed from balances — use Reports → Stock Inventory for value detail.

Q: How do I manage campuses and offices?
A: Via API today; web Organization page shows departments. Ask your administrator or integrator.

Q: What currency is used?
A: Philippine pesos (₱) for costs, depreciation, and reports unless configured otherwise at deployment.

Q: Can HRIS see my assigned assets?
A: Yes — assigned assets sync via internal custodianship API when HRIS is configured with the service key.

Chapter 19 — Best Practices (Staff)

  • Set minimum stock and reorder points on items you manage — dashboard alerts depend on them.
  • Always reconcile physical counts before closing; unresolved variances affect COA RPCPPE accuracy.
  • Run depreciation only after profiles are verified with finance.
  • Prefer barcode/QR scan over manual entry in Field Mode and stock receiving.
  • Use requisitions for controlled issuing rather than ad-hoc issues when policy requires approval.
  • Generate PAR/ICS promptly when assigning PPE to custodians.
  • Export reports on a fixed calendar (monthly stock, annual property ledger) — do not rely only on dashboard widgets.
  • Keep administrator accounts few; use Supply Officer, Property Custodian, or Supply Clerk for daily work.
  • Sign out on shared field tablets after each shift.
  • Never commit .env files or SERVICE_API_KEY to source control.

Part 2 — Quick Start Guide

15-minute setup (local)

  1. Ensure HRIS Postgres is running (127.0.0.1:15432, database hris_payroll).
  2. Copy api/.env.example → api/.env; set DB_SCHEMA=uims.
  3. Run migrations and seed:
    cd UIMS
npm install
npm run db:migrate
npm run db:seed
  4. Start API: npm run dev:api (port 3334).
  5. Start web: npm run dev:web (port 5200).
  6. Login: admin@uims.local / password123.
  7. Verify dashboard loads with seeded org, warehouse, and supplier.
  8. Optional: receive sample stock on Stock → Receipt (IN).
  9. Optional: register one asset and assign to a custodian.
  10. Optional: configure Identity and launch via SSO (AUTH_MODE=dual).

Daily Supply Office checklist

  1. Sign in to UIMS web (or SSO).
  2. Review dashboard Low Stock and Near-Expiry panels.
  3. Process pending requisitions (approve / fulfill).
  4. Post receipts for deliveries received overnight.
  5. Glance at recent stock movements for anomalies.
  6. Follow up on open physical count sessions.

Part 3 — Administrator Guide

Bootstrap & seeders

The main seeder creates:

  • All roles and 27 permissions

Security checklist

  • Change default admin password after first login.
  • Store secrets in env / secret manager only.
  • Restrict users.write, roles.write, and org.write to trusted administrators.
  • Review audit logs periodically.
  • Enable HTTPS/TLS in production for web and API.
  • Rotate SERVICE_API_KEY and DB credentials on schedule.

Backups & disaster recovery

Cadence Action
Daily Incremental DB backup; verify job success
Weekly Full logical dump (pg_dump) of uims schema/database
Offsite Copy dumps to second region or cold storage
Quarterly Restore drill to staging; document RTO/RPO

Data privacy (RA 10173)

  • Treat user profiles, custodianship assignments, and audit trails as personal/organizational data.
  • Limit access via RBAC; do not export PII beyond authorized reports.
  • Prefer SSO over shared passwords.
  • Document processing purpose (inventory & property accountability) in the university privacy notice.

Part 4 — Field PWA Guide

Audience

Warehouse staff, property custodians, and count teams using tablets or phones during physical inventory.

Install UIMS Field

Connect to a count session

  2. Or enter barcode manually with quantity.
  3. GPS and optional photo attach to each line.

After the walk

  1. Return to desktop Physical Count session.
  2. Review scan lines and variances.
  3. Reconcile → Close.

Part 5 — SSO & Platform Access Guide

Audience

Campus IT, Identity administrators, and users launching UIMS from the enterprise portal.

Platform registration

  1. Register UIMS in Identity with platform code uims.
  2. Set callback URL to {WEB_ORIGIN}/sso/callback.
  3. Configure API PLATFORM_* variables to match Identity issuer and JWKS.

User launch flow

  1. User signs in to University Platform Access.
  2. Clicks UIMS tile.
  3. Identity redirects to /sso/callback#access_token=…&refresh_token=….
  4. UIMS stores tokens, calls /auth/me, maps platform permissions, redirects to dashboard.

Auto-provision

When PLATFORM_AUTO_PROVISION=true, first SSO login creates a local user linked to the platform identity. Default org code comes from PLATFORM_DEFAULT_ORG_CODE. Use with explicit role assignment policy.

Troubleshooting SSO

Issue Fix
Blank callback page Re-launch from Identity; tokens must be in URL hash
401 on /auth/me Check JWKS URL, issuer, audience
User has no permissions Assign UIMS roles locally or map platform claims
SSO works but local login disabled Expected when AUTH_MODE=platform

Part 7 — Frequently Asked Questions

What apps make up UIMS?
UIMS Web (React/Vite SPA) and UIMS Field PWA, both backed by one AdonisJS API.

Is UIMS multi-tenant?
Organization-scoped; demo org code is UNI.

Does UIMS use the CDTS database?
No. It uses the same Postgres as HRIS_PAYROLL with schema uims.

Do we need Identity for local dev?
No. Local login works with default seed. Enable SSO when Identity is available.

Where is the API contract?
Swagger at http://127.0.0.1:3334/api/v1/docs and architecture doc at docs/ARCHITECTURE.md.

Can supply clerks approve COA forms?
Only if granted coa.write. Default Supply Clerk role does not include COA write.

Is Redis required?
Recommended for multi-replica idempotency and rate limits; single-node dev uses in-memory stores.

Part 8 — Troubleshooting

Staff web

  • Blank data → empty seed or missing permissions.
  • Permission denied → role lacks code; ask admin.
  • CSV import partial success → read errors[] in response toast or network tab.

Field PWA

  • Cannot sync → count session not open; verify Count ID.
  • Camera scan unavailable → use manual entry; browser may lack BarcodeDetector.
  • Offline badge persists → check Wi‑Fi; tap Sync.

API / database

  • Migration errors → confirm DB_SCHEMA=uims and HRIS DB is reachable.
  • Wrong schema data → never point UIMS at HRIS public schema without DB_SCHEMA=uims.

SSO

  • Tokens missing → launch from Identity, not direct /sso/callback bookmark.
  • CORS on Identity → include UIMS web origin in Identity allowed clients.

Part 10 — Best Practices

  1. Configure org structure (campuses, offices, departments) before go-live inventory loading.
  2. Load master items via CSV in batches ≤ 2000 rows; validate SKUs first.
  3. Post beginning balances before operational receive/issue when migrating legacy data.
  4. Enforce requisition approval for all office issues per campus policy.
  5. Tie PAR approval to asset assignment the same day custodian takes possession.
  6. Close physical count sessions within the count period; do not leave sessions open indefinitely.
  7. Run depreciation monthly after finance cutoff; reconcile with property ledger report.
  8. Export and archive reports per COA and institutional records schedule.
  9. Use SSO in production; disable or rotate local passwords for non-break-glass accounts.
  10. Test Field PWA install and sync on the actual warehouse Wi‑Fi before annual inventory.

Part 11 — Task: Create an Item

  1. Inventory → Items → Add.
  2. Enter SKU, name, UOM, and optional barcode, brand, model.
  3. Set minimum stock and reorder point for dashboard alerts.
  4. Assign a category.
  5. Save.
  6. Optional: receive initial quantity under Stock → Receipt (IN).

Bulk alternative: prepare CSV → Import CSV → review created/updated counts and errors.

Part 12 — Task: Receive Stock

  1. Confirm the item exists in Items and the target warehouse (and bin if used).
  2. Inventory → Stock → Movements → Receipt (IN).
  3. Select item, warehouse, bin, quantity, and reference (PO number, delivery receipt).
  4. Post.
  5. Open Balances tab — verify on-hand increased.
  6. Check Recent Stock Movements on dashboard.

For integrations, send Idempotency-Key: {uuid} on the API POST /stock/receive request.

Part 13 — Task: Assign an Asset

  1. Property → Assets — register asset if not yet created (property number, type, cost, in-service date).
  2. Open asset detail → Assign.
  3. Select custodian (employee or office).
  4. Confirm — status becomes assigned.
  5. Generate QR and print label for the physical item.
  6. Create PAR (or ICS for semi-expendable) under COA Forms → link asset → Approve.

Part 14 — Task: Create ICS / PAR

  1. Property → COA Forms → New.
  2. Select type ICS (semi-expendable) or PAR (PPE).
  3. Fill header: custodian, office, date, remarks.
  4. Add lines — link registered assets or items as required.
  5. Save as draft; review with custodian.
  6. Approve — document number assigned (e.g. PAR-2026-0001); approval audited.
  7. Export CSV for printing and filing.

Part 15 — Task: Run a Physical Count

  1. Inventory → Physical Count → New — warehouse, type (stock or property).
  2. Note Count ID; share with field team.
  3. On tablet: Field Mode → enter Count ID → scan items/assets → Sync.
  4. Desktop: open session → review lines and variances.
  5. Reconcile — system posts adjust movements for variances.
  6. Close session.
  7. For PPE: prepare RPCPPE COA form referencing the closed count.

Part 16 — Task: Run Depreciation

  1. Ensure each asset has a depreciation profile (useful life, residual rate, in-service date).
  2. Property → Depreciation → Run Depreciation.
  3. Select year and month for the period.
  4. Run for all assets or one asset.
  5. Review entries on Property Ledger tab.
  6. Export Depreciation report for finance (reports.export).

Do not re-run the same period expecting duplicate entries — runs are idempotent per asset/month.

Part 17 — Task: Export a Report

  1. Reports → choose report (Stock Inventory, Property Ledger, Consumption, or Depreciation).
  2. Apply filters (dates, warehouse) if shown.
  3. Download CSV for spreadsheet analysis.
  4. Or Print / PDF for signed hardcopy.
  5. Archive per records policy.

Requires reports.read to view and reports.export to download.

Part 18 — Task: Manage Users

  1. Settings → Users → Create.
  2. Enter email, full name, temporary password (or rely on SSO auto-provision).
  3. Assign role: e.g. Supply Clerk for receiving desk, Property Custodian for department assets.
  4. User signs in and verifies menu access matches duties.
  5. To revoke access: deactivate user or remove elevated roles.
  6. Never share the seeded admin@uims.local password across operators.

Part 19 — Task: Launch via SSO

  1. Campus IT registers UIMS in Identity (uims, callback /sso/callback).
  2. API .env sets AUTH_MODE=dual and all PLATFORM_* variables.
  3. User opens University Platform Access portal.
  4. Clicks UIMS.
  5. Lands on dashboard — confirm name and role under profile / users.
  6. If permissions missing, administrator assigns UIMS role to the linked local user.

Fallback: on login page, use local email/password when AUTH_MODE=dual.
