1. Overview

DocsTrack exposes a versioned REST API for tenant registration, document lifecycle, workflows/approvals, search, billing, notifications, AI copilot, and platform administration.

Surface Prefix Auth
Infrastructure /, /health/*, /metrics Public (metrics gated in production)
Public tracking & assets /track/*, /uploads/*, /api/v1/public/* Public
Authentication /api/v1/auth/* Public
Tenant account /api/v1/account/* Bearer JWT + tenant context
Platform admin /api/v1/admin/* Bearer JWT + super-admin
Billing webhooks /api/v1/webhooks/billing/* Provider signature (no JWT)

Approximate route count: 158 HTTP registrations.

Content type for JSON bodies: application/json unless uploading multipart files.

2. Authentication & Tokens

2.1 Token types

Token Lifetime (typical) Use
Access token (JWT) Short-lived (~15 min / expiresIn) Authorization: Bearer <accessToken>
Refresh token Longer-lived POST /api/v1/auth/refresh
MFA challenge token Short-lived Complete MFA after login

Successful login / register / MFA / refresh returns:

{
  "user": {
    "id": "uuid",
    "email": "owner@demo.com",
    "fullName": "Demo Owner",
    "tenantId": "uuid",
    "isSuperAdmin": false,
    "emailVerified": true,
    "mfaEnabled": false
  },
  "tokens": {
    "accessToken": "…",
    "refreshToken": "…",
    "expiresIn": 900,
    "tokenType": "Bearer"
  }
}

When MFA is required at login:

{
  "mfaRequired": true,
  "mfaChallengeToken": "…"
}

Then call POST /api/v1/auth/mfa/challenge with { "mfaChallengeToken", "mfaCode" }.

2.3 Register body (required)

email, password, passwordConfirmation, fullName, organizationName

Password rules: typically 8–32 characters (enforced by VineJS validators).

2.4 Session logout

POST /api/v1/account/logout — requires authenticated account context; invalidates current session/refresh pair as implemented by the auth service.

3. Multi-Tenancy

  • Tenant membership is bound to the authenticated user (user.tenantId).
  • Account routes require auth + tenant middleware.
  • Super-admins may operate across tenants; the web client can send X-Tenant-Id for impersonation / context override when allowed by the API.
  • Data isolation is enforced in repositories and policies (documents, drafts, files, etc.).

Always send the access token on account and admin routes. Do not rely on tenant id alone.

4. Headers & Conventions

Header Required Description
Authorization Account / Admin Bearer <accessToken>
Content-Type JSON writes application/json
X-Tenant-Id Optional Super-admin / client override when supported
Accept Optional Prefer application/json

Path params: UUIDs unless noted (e.g. tracking numbers, filenames).

Pagination: list endpoints typically accept page, limit (and sometimes cursor/search query params). Check OpenAPI for each operation.

Idempotency: Prefer safe retries on GET. Mutations (POST/PUT/PATCH/DELETE) should not be blindly retried without client-side guards.

5. Error Model

Failed requests generally return JSON with an error payload, for example:

{
  "error": "Unauthorized"
}

Validation failures may include field-level messages from VineJS. HTTP status codes follow REST norms:

Status Meaning
200 / 201 Success
400 Validation / bad request
401 Missing or invalid token
403 Authenticated but forbidden (permission / tenant)
404 Resource not found (or metrics disabled)
409 Conflict (duplicate, state machine)
413 Payload too large
429 Rate limited
500 Server error

Frontend clients normalize Axios errors into ApiError (see web/docs/API_LAYER.md).

6. Rate Limiting & Throttling

  • Auth and account route groups use Adonis limiter middleware (Redis or memory store).
  • Public tracking (GET /track/:trackingNumber) has a dedicated throttle.
  • Respect 429 responses; back off and retry with jitter.

Exact limits are environment-configurable via limiter config — treat documented OpenAPI/Swagger as the contract for request shapes; treat ops config for numeric quotas.

10. Common Workflows

10.1 Login → list documents

  1. POST /api/v1/auth/login
  2. Store tokens; send Authorization: Bearer …
  3. GET /api/v1/account/documents

10.2 Create → upload → submit

  1. POST /api/v1/account/documents
  2. POST …/versions/:versionId/files (or presign flow)
  3. POST /api/v1/account/documents/:id/submit

10.3 Approve

  1. GET …/approvals or approvals queue via list filters
  2. POST …/approvals with action payload (approve / reject / …)

10.4 Public tracking

  1. Obtain tracking number from document
  2. GET /track/:trackingNumber (no auth)

10.5 Token refresh

  1. On 401, call POST /api/v1/auth/refresh with refreshToken
  2. Retry original request with new access token
  3. If refresh fails, force re-login

11. Webhooks

Billing providers POST events to /api/v1/webhooks/billing/{stripe|paymongo|stub}.

  • Verify signatures using provider secrets (STRIPE_WEBHOOK_SECRET, PAYMONGO_WEBHOOK_SECRET).
  • Respond quickly with 2xx; processing may enqueue side effects.
  • Stub webhook is for local/dev when BILLING_PROVIDER=stub.

12. Realtime & Background Jobs

Not REST, but part of the integration surface:

System Purpose
Socket.IO Live notifications / document events (when enabled)

Clients should treat REST as source of truth and use realtime as an optimization.
