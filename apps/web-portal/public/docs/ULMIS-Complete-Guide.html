Chapter 1 — Introduction

Purpose of the System

ULMIS is a university-focused library management platform. Institutions use it to:

  • Maintain a bibliographic catalog with copies, barcodes, and import tools (CSV, MARC JSON, Excel)
  • Manage members (students, faculty, staff) and membership approval
  • Run circulation: requests, checkout, return, renew, mark lost
  • Operate holds/reservations and fines in Philippine pesos (₱)
  • Offer a public OPAC, member portal, and self-service kiosk
  • Support queue display, resource locator, and attendance logging
  • Export mandated reports and monitor audit activity

Key Benefits

Benefit Business value
Multi-app clients Staff, public OPAC, and kiosk share one API
Policy blocks Overdue / unpaid fines / membership rules enforced on borrow
Import pipeline Bulk load from CSV, MARC, or Excel
Self-service Kiosk checkout/return with device keys
Traceability Audit logs for sensitive actions
Campus hooks ARIS/HRIS sync UI; SMTP/Twilio when configured

Chapter 2 — Accessing the System

Local URLs (development)

Surface URL

Kiosk http://localhost:5175
API / Swagger http://localhost:3333/api/v1/docs

Staff login

  1. Open the staff web URL.
  2. Enter tenant slug ulmis when prompted (or rely on default VITE_DEFAULT_TENANT_SLUG).
  3. Sign in with your staff email and password.

Preferred training access (University Identity):

Email Typical use
admin@identity.local All platforms + Identity admin
employee@identity.local Library + HRIS + DocsTrack
student@identity.local Library / OPAC only
nodocs@identity.local Library + HRIS (no DocsTrack)

Password is the value of DEMO_SEED_PASSWORD in the Identity API environment. Sign in at the Identity portal, then launch Library from the platform launcher.

Legacy local bootstrap (non-production only): admin@university.library — rotate immediately; do not document a shared password.

Session tips

  • If API calls fail with 401, sign out and sign in again (token expired).
  • Confirm the API is running and CORS includes your client origin.
  • Tenant slug must be correct — do not use a campus location name as the slug.

Chapter 4 — Dashboard Overview

The dashboard aggregates circulation health: active loans, overdue, pending requests, attendance summary, and configurable widgets.

  • Toggle widgets in Settings (or dashboard preferences where available).
  • Export a summary PDF when the control is shown on the dashboard.
  • Scheduled email reports require SMTP + background queue worker (queue:listen).

Chapter 5 — Catalog & Inventory

Create a title

  1. Open Books → Add (or equivalent).
  2. Enter title, authors, ISBN, category, and description.
  3. Save, then add copies with barcodes and location.

Copies

  • Each physical item is a copy with a unique barcode.
  • Statuses include available, on loan, lost, etc.
  • Circulation always binds to a copy, not only the title.

Import

Format Where
CSV file Catalog → Import CSV
MARC JSON Catalog → Import MARC
Excel .xlsx Catalog → Import Excel

After import, open the title’s Versions panel to review catalog history.

Digital files on a book

Attach files from the book detail screen; authorized users can download via the digital-file endpoint / UI.

Chapter 6 — Members

Register a member

  1. Members → create.
  2. Capture name, email, member number / ID, membership type.
  3. If approval is required, the record stays pending until a librarian approves.

Approve / reject

Use Pending list → Approve or Reject.

Card & history

  • Card view for membership card data.
  • Borrowing history for past loans.

Suspended or unpaid-fine members may be blocked from new loans by policy.

Chapter 7 — Circulation

Checkout (desk)

  1. Identify the member (search by name, number, or barcode).
  2. Scan or select an available copy.
  3. Complete Checkout. System applies due dates and borrow blocks.

Return

  1. Find the active loan (scan barcode or search).
  2. Return. Overdue items may generate fines in ₱.

Renew

Renew from staff circulation or member portal when policy allows.

Mark lost

Use Mark lost when an item will not be returned; follow local fine/replacement policy.

Borrow blocks

Typical blocks: overdue items, unpaid fines, inactive membership. Resolve the underlying issue before retrying checkout.

Chapter 8 — Reservations & Fines

Reservations (holds)

  1. Create a reservation for a title/member when copies are unavailable.
  2. When ready, Fulfill (mark ready for pickup) per desk procedure.
  3. Cancel if the patron no longer needs the item.

Fines

  • View fine list and summary.
  • Collect payments (record amount received).
  • Waive or adjust with appropriate permission.
  • Review payment lines for auditability.

Currency: PHP (₱).

Chapter 9 — Digital Repository

  • Create repository items and grant access (view/download) to authorized users.
  • Manage e-resources (external URLs) and open them from the UI.
  • Search across digital holdings from the Digital module.

Chapter 10 — Reports & Analytics

On-demand exports

Open Reports and export the university-mandated report types (CSV/PDF as implemented). Permission: reports:export.

Analytics

Dashboard analytics require analytics:read. Use for collection and circulation insight—not as a substitute for official exports.

Scheduled email

Administrators configure schedule under Settings. Requires:

  1. Valid SMTP_* on the API
  2. Queue worker running
  3. Recipient preferences as configured

Chapter 11 — Attendance

Log walk-in / visit events under Attendance. Summary counts appear on the dashboard. Use for gate/counter tallies and daily activity reporting.

Chapter 12 — Settings & Users

Settings

Admins with settings:update can edit:

  • Institution branding and display name
  • Public links (OPAC, help)
  • Notification / report preferences
  • Dashboard-related toggles where exposed

Users

Admins manage staff accounts under Users: invite/create, update roles, deactivate as needed. Prefer least-privilege roles (librarian, staff) over full admin.

Chapter 13 — Roles & Permissions

Role Summary
Administrator Full tenant permissions

Permission codes use resource:action (e.g. borrowings:checkout). See the API Specs Manual §7 for the full matrix.

Chapter 16 — Best Practices (Staff)

  • Always scan barcodes rather than typing when possible.
  • Resolve fines before forcing exceptions.
  • Rotate kiosk keys if a terminal is compromised or a key was truncated.
  • Export reports on a fixed calendar; do not rely only on dashboard widgets.
  • Keep admin accounts few; use librarian/staff for daily work.
  • Test SMTP in staging before enabling scheduled report mail.

Part 2 — Quick Start Guide

15-minute setup (local)

  1. Start API: npm run dev:api (from monorepo root or documented script).
  2. Start staff web: npm run dev:web.
  3. Login: University Identity admin@identity.local or student@identity.local (password from DEMO_SEED_PASSWORD), then launch Library; slug ulmis for local staff login if needed.
  4. Create one book + one copy with barcode.
  5. Create one active member.
  6. Checkout and return the copy.
  7. Optional: npm run dev:opac and search the title publicly.
  8. Optional: register a kiosk device, start npm run dev:kiosk, connect with full API key.

Daily desk checklist

  1. Sign in to staff web.
  2. Process overnight returns / overdue list.
  3. Clear reservation pickup shelf (fulfill / expire).
  4. Collect fines as patrons visit.
  5. Glance at attendance and queue board if used.

Part 3 — Administrator Guide

Bootstrap & seeders

  • University bootstrap / permission seeders create roles and the admin user.
  • In non-production, admin password may reset when ULMIS_RESET_ADMIN_PASSWORD (or equivalent) is enabled — see API .env.example.

Environment essentials

Variable area Notes
Database Migrate before first run
Redis / queue Required for scheduled jobs & some notifications
CORS_ORIGIN Include all three client ports
DEPLOYMENT_MODE=university ULMIS mode
SMTP / Twilio Optional channels
Client VITE_* API URL, tenant slug, OPAC/Kiosk URLs

Integrations page

Use Integrations to view adapter status and trigger ARIS/HRIS sync when campus credentials/jobs are ready. LDAP and Smart Campus SSO remain gated until verified.

Security checklist

  • Change default admin password.
  • Store secrets only in env / secret manager.
  • Rotate kiosk keys on device reassignment.
  • Restrict users:* and settings:update to trusted admins.
  • Review audit logs periodically.

Backups & ops

Follow campus backup policy for PostgreSQL/MySQL (as deployed) and uploaded digital files. Monitor API health and queue depth in production.

Part 4 — Public OPAC Guide

Audience

Students, faculty, and visitors searching the catalog without staff login.

How to search

  1. Open OPAC (http://localhost:5174 locally).
  2. Enter keywords (title, author, subject as supported).
  3. Open a result for availability and citations.
  4. Signed-in members (where linked) may add to reading list when portal auth is available in that UI flow.

Queue display

Public queue board route uses tenant-scoped GET /api/v1/public/queue/board — suitable for lobby screens via OPAC /queue when enabled.

Tips

  • Ensure X-Tenant-Slug / default slug is ulmis.
  • OPAC does not replace circulation desk for checkout unless your campus also provides kiosk or portal renew.

Part 5 — Kiosk Self-Service Guide

Staff: register a device

  1. Staff web → Kiosk Platform.
  2. Register device: set an exact device code (e.g. KIOSK-001) and label/location.
  3. Copy the API key immediately (shown once). Store it in the kiosk app or secure device config.
  4. If lost, Rotate key and update the kiosk.

Kiosk app setup

  1. Open http://localhost:5175 (or campus kiosk URL).
  2. Enter:
    • Tenant slug: ulmis
    • Device code: exact match (e.g. KIOSK-001)
    • API key: full ksk_… value
  3. Save. The home screen shows Borrow / Return / Account / History.

Patron flow

  1. Identify with member number / barcode as prompted.
  2. Borrow: scan item barcode(s) → confirm.
  3. Return: scan item(s) → confirm.
  4. Account / History: view loans and recent activity.
  5. Idle timeout logs the patron out automatically (server time).

Common kiosk mistakes

Mistake Result
Tenant = location name Auth fails
Device code typo 401 / unknown device
Truncated API key 401 — rotate and re-enter

Part 8 — Frequently Asked Questions

What apps make up ULMIS?
Staff web, public OPAC, kiosk, and shared API.

Is multi-tenant?
Yes. University demo tenant slug is ulmis.

Can we connect Active Directory today?
API surface exists; expect 501 until campus IdP is verified and configured.

Do we need Redis?
Recommended for queues (scheduled reports, async notifications).

Where is the API contract?
Swagger at /api/v1/docs and API-Specs-Manual.md.

Is there a load certification?
A smoke script exists; formal 300-concurrent certification is an ops exercise — see compliance NFR notes.

Part 9 — Troubleshooting

Staff web

  • Blank data → wrong tenant or empty seed.
  • Permission denied → role lacks permission; ask admin.
  • PDF/export empty → check report type and date filters.

OPAC

  • No results → catalog empty or wrong slug.
  • Citations missing → title lacks metadata fields used by citation builder.

Kiosk

  • Cannot connect → verify code, full key, slug ulmis, API up, CORS.
  • Checkout blocked → member policy (fines/overdue); resolve in staff web.

Email / SMS

  • Prefs on but nothing sent → env not set or queue worker not running.

Part 11 — Best Practices

  1. Prefer barcodes over manual IDs.
  2. Keep kiosk keys offline-secret; never commit them to git.
  3. Run imports first in a staging tenant.
  4. Document local due-date and fine policies for desk staff.
  5. Review audit logs after bulk waives or user role changes.
  6. Keep OPAC and kiosk URLs in tenant settings / env for consistent linking.

Part 12 — Task: Catalog a Title

  1. Books → Add title → fill metadata → Save.
  2. Add copy → assign barcode → set location → Save.
  3. Search in staff OPAC or public OPAC to verify visibility.
  4. Optional: attach a digital file.

Part 13 — Task: Check Out and Return

  1. Members → ensure patron is active.
  2. Borrowings → Checkout → select member + copy.
  3. Confirm due date.
  4. Later: Return → scan copy → confirm.
  5. If overdue, open Fines → Collect.

Part 14 — Task: Import Catalog

  1. Prepare CSV/XLSX with required columns (see import UI hints) or MARC JSON payload.
  2. Catalog → Import → upload / paste → submit.
  3. Review success/error counts.
  4. Open a sample title → Versions.

Part 15 — Task: Register a Kiosk

  1. Kiosk Platform → Register → KIOSK-001 + label.
  2. Copy full API key.
  3. On kiosk app, enter ulmis, KIOSK-001, key → Connect.
  4. Test patron lookup and a return or checkout with a sample item.
  5. Confirm heartbeat / session in platform list.

Part 16 — Task: Export Reports

  1. Reports → choose type (e.g. circulation, overdue, inventory — as listed).
  2. Apply date filters if prompted.
  3. Download file.
  4. Archive per university records policy.

Part 17 — Task: Manage Users

  1. Users → Create / invite → assign role (librarian or staff).
  2. User signs in and verifies menu access.
  3. To revoke: disable or remove role via update flow.
  4. Never share the seeded admin password across operators.
